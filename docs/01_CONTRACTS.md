## M1: отладочный транспорт direct-http

Режим по умолчанию для M1 — `ASSISTANT_TRANSPORT=direct-http` (см. `.env.example`).
Сервис: FastAPI, `http://127.0.0.1:8770`, знания из `knowledge/pack.json`
(`knowledge_source = fallback`).

| Метод | Путь | Назначение |
|---|---|---|
| `GET` | `/health` | модель, доступность LLM, источник знаний, версия pack, оценка токенов |
| `POST` | `/dialog` | создать диалог, вернуть `dialog_id` |
| `POST` | `/ask` | вопрос, ответ потоком SSE |
| `GET` | `/history/{dialog_id}` | история диалога в памяти сервиса |
| `POST` | `/cancel` | мягкая отмена по `message_id` |

События SSE `/ask`:

| event | data | Когда |
|---|---|---|
| `meta` | `message_id`, `dialog_id`, `state` | сразу после принятия запроса |
| `delta` | `text` | куски уже провалидированного ответа |
| `done` | `message`, `model`, `prompt_version`, `pack_version`, `latency_ms`, токены | успех |
| `cancelled` | `message` | отмена пользователем |
| `error` | `message_id`, `error`, `state` | LLM недоступна, таймаут, внутренняя ошибка |

Особенности реализации M1:

1. **Ответ буферизуется.** Сначала LLM генерирует текст целиком, затем он
   валидируется (FR-13), и только после этого SSE отдаёт готовые куски.
   Потоковость первого токена принесена в жертву отсутствию выдуманных
   идентификаторов. Для NFR-2 это допустимо: первый `delta` приходит после
   полной генерации (~1–3 с на профиле A).
2. **Отмена в direct-http жёсткая по потоку и мягкая по смыслу.** Панель
   прерывает fetch и вызывает `/cancel`; сервис выставляет событие, агент
   прекращает ожидание следующего куска. Уже начатая генерация Ollama может
   дойти до конца, но результат не попадёт в ответ.
3. **История диалога — в памяти процесса.** Она теряется при перезапуске
   сервиса; запись конструкций диалога в БЗ появится в M2-T7/T8.
4. **Панель передаёт в `cancel()` локальный id сообщения.** `DirectHttpTransport`
   сам запоминает серверный `message_id` из события `meta` и отправляет его в
   `/cancel`. Контракт `AssistantTransport` при этом не меняется; транспорт
   `sc-memory` в M2 будет сопоставлять id со своим узлом действия.
5. **CORS** разрешён только для `http://127.0.0.1:5173` и
   `http://localhost:5173` (dev-стенд панели). Для встраивания в редактор
   панель работает через sc-память, поэтому CORS не нужен.

## M1: контракт валидатора

- Регулярка: `\b(?:concept|nrel|rrel|action)_[A-Za-z0-9_\u0400-\u04FF]+\b`.
- Белый список: существующие идентификаторы ∪ новые ∪ **ключи свойств**
  (`PROPERTY_KEYS`). Ключ `action_id` совпадает с префиксом `action_*`, поэтому
  без ключей свойств он ошибочно считался бы галлюцинацией.
- Один repair-запрос к модели; если неизвестные остались — они вырезаются,
  в конец ответа добавляется `[часть ответа удалена: неизвестные идентификаторы]`,
  инцидент пишется в журнал.
- `hallucinated_id_rate` считается по наличию неизвестных **до** валидации,
  а не по финальному тексту.
- Основания ответа (`sources`) — только идентификаторы, реально поданные в
  промпт (типы, свойства, отношения из pack), а не любые слова модели.

## M1: известные ограничения

| Ограничение | Причина | План |
|---|---|---|
| Нет sc-транспорта | M2-T8/T9 | M2 |
| Нет записи диалога в БЗ | M2-T7 | M2 |
| Нет принципов/методики в ответах | pack M1 содержит только каталог; тексты появятся в M2-T2 | M2 |
| Стрим только после полной генерации | FR-13 важнее потоковости | этап 2, при необходимости |
| `on_event` заменён на lifespan | deprecation FastAPI | сделано |
| Один активный запрос на транспорт | защита от гонок UI | очередь воркеров — этап 2 |
