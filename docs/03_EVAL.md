# 03. Оценка качества

Отчёты и сырые ответы — `eval/reports/`. Дата финального прогона: 2026-11-18.

## 1. Методика

### 1.1. Gold-набор

`eval/gold_questions.jsonl` — 46 вопросов со следующим распределением:

| Категория | Вопросов |
|---|---|
| `catalog_type` | 10 |
| `catalog_prop` | 8 |
| `list` | 4 |
| `compare` | 6 |
| `principle` | 5 |
| `methodology` | 4 |
| `environment` | 3 |
| `negative` / `out_of_scope` | 4 / 2 |

Строка содержит `id`, `category`, `question`, `must_contain`, `must_not_contain`,
`reference_answer` и необязательные поля:

- `must_contain_any` — список групп альтернатив; в каждой группе достаточно одного
  совпадения. Используется там, где корректный ответ может дать русское название,
  системный идентификатор или морфологический вариант («внутри меню» / `nrel_ui_contains`);
- проверка идёт по нормализованному тексту: нижний регистр, `ё → е`, удаление обратных
  кавычек и `**`. Совпадение — по подстроке, поэтому ключ `visible` засчитывается
  и внутри `concept_ui_visible`.

Проверки уточнялись по итогам первого прогона (не «под ответ», а под эквивалентные
формулировки): приняты ключи свойств (`opacity`, `corner_radius`), корни слов
(`строч`, `пользовател`), идентификаторы принципов `ui_principle_*` и смысловые
варианты отказа («нет сведений», «нет компонента», «нет отдельного типа»).

### 1.2. Прогон

Инструмент: `tools/run_eval.py`, цель `make eval ARGS="..."`.

```bash
.venv/bin/python tools/run_eval.py --label profile-a-final
.venv/bin/python tools/run_eval.py --model qwen3.5:9b --label profile-b
.venv/bin/python tools/run_eval.py --source pack --label fallback
```

- ответы идут через `KnowledgeService` (тот же путь, что у sc-агента), не через HTTP;
- знания читаются из sc-памяти (`--source kb`, по умолчанию), при `--source pack` — из
  локального `pack.json`;
- перед замером делается прогрев (в метрики не входит);
- VRAM peak снимается `nvidia-smi` раз в 0.5 с;
- `temperature=0.2`, `top_p=0.9`, `num_ctx=8192`, `think=false`;
- выход: `eval/reports/<дата>_<модель>_<метка>.md` и `.jsonl` с каждым ответом.

Метрики: `accuracy`, `hallucinated_id_rate` (неизвестный идентификатор **до** валидации),
`refusal_correctness` (точность на `negative` + `out_of_scope`), p50/p95/max латентности,
prompt/output tokens, VRAM peak.

### 1.3. Guard идентификаторов

Если в вопросе встречается системный идентификатор вне замороженного контракта,
сервис **не передаёт вопрос в LLM** и возвращает детерминированный отказ. Причина:
модель 4B склонна цитировать такой идентификатор даже при отказе, что давало ложный
`hallucinated_id_rate` до 2.2% и зависело от запуска. Вопрос в журнале и БЗ сохраняется
исходным; в отчёте такие вопросы помечаются отдельной строкой `guard: вопрос не отправлен в LLM`.

## 2. Итерации промпта

| Версия | Суть | accuracy | hall. | refusal |
|---|---|---|---|---|
| `prompt_v1.md` | первоначальная версия | 63.0% (29/46) | 2.2% | 33.3% |
| `prompt_v2.md` | полнота перечислений, общие свойства, запрет повтора id из вопроса | 91.3% (42/46) | 2.2% | 100% |
| `prompt_v3.md` | счётчики в рендере, полнота этапов, few-shot со списком свойств и отказом, guard | **100%** | **0%** | **100%** |

`prompt_v3.md` закреплён в `Settings.prompt_path` и `.env.example` (`PROMPT_VERSION=v3`).

Рендер знаний добавил в разделы строки `типов: 16`, `свойств: 27 (все типы)`,
`принципов: 5`: модель перестала пропускать последний элемент при перечислении.
Бюджет блока ЗНАНИЙ — **3497 токенов** из 3500; при превышении рендер усекает
methodology/environment до заголовков (тест `test_knowledge_fits_budget`).

Отчёты: `eval/reports/2026-11-18T07-40-08_qwen3.5-4b_profile-a-final.md`,

Профиль C влезает в 8 ГБ и работает быстрее всех, но не проходит порог корректных
отказов: пропускает этапы методики (`q035`–`q037`), путает модули среды (`q039`)
и вместо отказа предлагает `concept_ui_image` как видеоплеер (`q042`). Поэтому
по умолчанию остаётся профиль A; профиль B можно использовать для качества,
он также целиком в VRAM (`ollama ps` → `100% GPU`, ctx 8192).

Повторяемость профиля A: четыре полных прогона — 100% / 100% / 97.8% / 100% при
`hallucinated_id_rate = 0` и `refusal_correctness = 100%`. Единственный провал —
ответ со списком принципов в виде `ui_principle_*` вместо русских названий; проверка
q021 дополнена `must_contain_any`, после чего повторный прогон снова дал 100%.
Пороги качества: accuracy ≥ 85%, галлюцинаций 0, отказы ≥ 90%, p95 ≤ 20 с.

## 4. Известные ограничения

- Проверки строятся на подстроках и корнях, а не на семантической эквивалентности;
  спорные случаи разбираются вручную по `*.jsonl`.
- Замер latency делается без стриминга в панели; для индикации обработки важно,
  что статус появляется за 58–86 мс, а не «ответ за 2 секунды».
- `on_event` занимает поток sc-событий до ~20 с; для однопользовательской среды
  допустимо.
- Профиль C не используется как рабочий из-за низкой корректности отказов.
