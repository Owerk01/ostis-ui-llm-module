# 03. Оценка качества

Финальные прогоны: 2026-11-18. Отчёты и сырые ответы — `eval/reports/`.

## 1. Протокол

- Разделены выборки: `eval/gold_questions.jsonl` (dev, 46 вопросов, использовалась
  при настройке промпта) и `eval/holdout_questions.jsonl` (29 вопросов, та же
  структура категорий, **не использовалась** для настройки).
- Перед финальными прогонами зафиксированы SHA-256 обеих выборок и шаблона
  `prompt_v4.md` в `eval/frozen.json`. Хэши и версия промпта выводятся в каждом
  отчёте; при расхождении хэша dev-выборки отчёт помечается `tainted: true`.
- Holdout прогнан **один раз**, проверки после этого не менялись.
- Все ответы финального dev- и holdout-прогона размечены вручную в
  `eval/manual_review.jsonl`: `correct | partial | incorrect`, с перечнем
  неверных утверждений.
- Автопроверки (`must_contain`, `must_not_contain`, `must_contain_any`) остались
  усилены по Приложению B FIXES.md; ослаблений после провалов не делалось.
- Бюджет промпта разделен: знания 3500, история 800, экземпляр 1500, резерв
  вывода 512 (итого 6312). `LLM_NUM_CTX` остался 8192: новых замеров VRAM не
  проводилось, контекст молча не расширялся. При нехватке места усекается блок
  экземпляра. Заморозка `prompt_v4.md` и gold-метрики не пересматривались.

## 2. Метрики

| Метрика | Определение | Порог |
|---|---|---|
| `accuracy` | доля вопросов, прошедших автопроверки | информационная |
| `hallucinated_id_rate` | неизвестный id **до** валидации | информационная |
| `unknown_id_in_final_rate` | неизвестный id в финальном тексте (каталог + экземпляр) | **0** |
| `unknown_catalog_in_final_rate` | неизвестный id каталога в финальном тексте | **0** |
| `unknown_instance_in_final_rate` | неизвестный id экземпляра в финальном тексте | **0** |
| `refusal_correctness` | точность на `negative` + `out_of_scope` | ≥ 0.90 |
| `injection_resistance` | доля инъекций без неизвестных id и без выполнения инструкции (≥ 5 вопросов) | ≥ 0.90 |
| `factual_accuracy` | `correct / total` по ручной разметке | ≥ 0.90 |
| `incorrect_count` | число ответов с verdict `incorrect` | 0 (цель, не достигнута) |
| latency | p50/p95 отдельно для тёплого и холодного кэша | p95 warm ≤ 20 с |

Раздельные метрики каталога и экземпляра добавлены без пересмотра порогов:
общая `unknown_id_in_final_rate` по-прежнему должна быть 0. Замороженные
выборки и `prompt_v4.md` не пересобирались; повторный прогон gold — отдельная
работа.

## 5. Ограничения методики

- Автопроверки работают на нормализованных подстроках и корнях слов; они
  чувствительны к форме («одну строку» vs «однострочный») и не понимают negation.
  Поэтому часть PASS/FAIL расходится с ручной разметкой (таблица выше).
- Для ключей свойств проверка использует границы слова, поэтому `visible` не
  засчитывается внутри `concept_ui_visible`.
- Dev-выборка использовалась при настройке промпта; её точность оптимистична.
  Holdout не настраивался, но показал более низкую корректность отказов —
  это честная оценка текущего состояния.
- Замер latency в тёплом режиме использует кэш префикса Ollama; холодный
  прогон с `keep_alive=0` показывает реальную цену загрузки модели (~4.8 с p50).
- Ручная разметка выполнена одним ревьюером (agent); для publishing-уровня
  нужен второй независимый ревьюер.
